# 23 — Named queries: move from `queries.toml` to a `queries/` directory of `.cypher` files

Status: ready-for-agent

## Parent

`.scratch/console-ergonomics/PRD.md` — implements **ADR 0020** (amending ADR 0012).

## What to build

Change where Named queries (issue 13) are stored: from the tool-managed
`~/.mgconsole/queries.toml` to a tool-owned directory `~/.mgconsole/queries/`,
one plain `.cypher` file per name (`<name>.cypher`). The directory is the source
of truth — there is no separate index. The four verbs are unchanged in surface
(`:save <name> [query]`, `:saved`, `:load <name>`, `:forget <name>`); only the
backing store changes.

Because the files are plain Cypher, the directory doubles as a `:source` library
(issue 10): a named query *is* a loadable script. Per ADR 0020 the console treats
the directory as authoritative and parses leniently — a hand-edited or
odd-looking file is tolerated and reported, never fatal.

Text-only template semantics are preserved exactly (issue 13): a file stores the
query text with its `$param` placeholders intact, resolved against the **current**
`:param` store at run time, and `:load` recalls into the input without auto-running.

This supersedes issue 13's `queries.toml`. No migration shim — the tool is
pre-release (ADR 0012), so there is no `queries.toml` in the wild to convert.

## Acceptance criteria

- [ ] `:save <name> [query]` writes `~/.mgconsole/queries/<name>.cypher`
      (text-only template); with no query given it saves the last query.
- [ ] `:saved` lists names by reading the directory; `:forget <name>` deletes the
      one file; both reflect the directory and leave the other files untouched.
- [ ] `:load <name>` places the file's template into the input for review/edit and
      does not auto-run; `$param` references resolve against the current `:param`
      store at run time.
- [ ] The same directory is readable by `:source <path>` (a named query is a
      loadable script — one format, not two).
- [ ] A name that maps to a missing/invalid file reports a clear error; an
      unparseable or oddly-named file in the directory is reported on `:saved`, not
      fatal (lenient-parse per ADR 0020).
- [ ] `MGCONSOLE_*` env overrides for the state directory still resolve the
      queries directory.
- [ ] The old `queries.toml` path is removed from the resolver/code; a comment
      records that ADR 0020 superseded it so a future reader doesn't restore it.
- [ ] The verbs behave identically in the REPL and Workbench.

## Agent Brief

**Category:** enhancement
**Summary:** Back Named queries with a directory of plain `.cypher` files instead of a single tool-managed TOML store.

**Current behavior:**
Named queries (issue 13) persist as a single `[queries]` table in a tool-managed
`queries.toml` under the state directory. The store type loads that one file and
rewrites it on every save/delete. The store is opaque: not greppable per query,
not git-diff-friendly per query, not hand-editable, and in a format only the tool
reads. The four verbs `:save` / `:saved` / `:load` / `:forget` drive it.

**Desired behavior:**
Each named query is one plain `.cypher` file (`<name>.cypher`) in a tool-owned
`queries/` directory under the state directory; the directory is the source of
truth with no separate index. Saving writes a file, `:forget` deletes one,
`:saved` lists by reading the directory. Files hold the query text with `$param`
placeholders intact, resolved against the **current** `:param` store at run time
(unchanged from issue 13). The same directory is a valid `:source` library — a
named query is a loadable script, one format not two. The console parses the
directory leniently (ADR 0020): an unparseable or oddly-named file is reported,
never fatal; a crash mid-write can leave at most one bad file, never a corrupt
index. No migration from `queries.toml` (pre-release, ADR 0012).

**Key interfaces:**
- The Named-queries store type (today loads/rewrites one TOML file) — should map
  a name to a file in a directory and mutate per-file, not rewrite a whole-store
  document.
- The queries-path resolver (today returns the path to a single file, honouring
  the `MGCONSOLE_*` state-dir overrides) — should resolve a *directory*, still
  honouring the same env overrides.
- The `:source` loader — confirm it reads files from the queries directory with
  no new format.

**Acceptance criteria:**
- [ ] `:save <name> [query]` writes `<state>/queries/<name>.cypher` (text-only

- [ ] `:saved` lists names from the directory; `:forget <name>` deletes only that
      file and leaves the rest untouched.
- [ ] `:load <name>` recalls the template into the input without auto-running;

- [ ] A named query file is loadable via `:source` (one format, not two).
- [ ] A missing/invalid name reports a clear error; an unparseable or oddly-named
      file in the directory is reported on `:saved`, not fatal.
- [ ] The `MGCONSOLE_*` state-dir overrides resolve the queries directory.
- [ ] The old `queries.toml` path is removed; a code comment records that ADR 0020

- [ ] The verbs behave identically in the REPL and Workbench.

**Out of scope:**
- The verb surface (`:save` / `:saved` / `:load` / `:forget`) — unchanged.
