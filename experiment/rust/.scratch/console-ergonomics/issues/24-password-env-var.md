# 24 — `MGCONSOLE_PASSWORD` env var for non-interactive auth

Status: ready-for-agent

## Parent

`.scratch/console-ergonomics/PRD.md`

## What to build

Add an environment-variable password path so an authenticated connection can be
made non-interactively without leaking the password to shell history or `ps`.
Today (`resolve_password`, `cli/src/lib.rs`) the only non-interactive options are
`--password X` on the CLI (lands in shell history and the process list) or a
plaintext password in `config.toml`; a username with no password otherwise
triggers a hidden prompt, which fails in a piped/scripted run.

Insert `MGCONSOLE_PASSWORD` into the password precedence chain:

```
explicit --password flag  >  MGCONSOLE_PASSWORD env  >  profile password  >  hidden prompt
```

So a script sets `MGCONSOLE_PASSWORD` and connects with no prompt and no CLI
leak; an explicit `--password` still wins (for parity with the existing flag);
the hidden prompt remains the interactive fallback when none of the above is set
and a username is given.

Deliberately **not** an OS keychain: keychain/secret-service is unreliable over
SSH, in containers, and in CI — exactly where a terminal Memgraph console runs —
and adds a dependency plus per-platform branches. An env var is the standard,
SSH-and-container-friendly path (cf. `PGPASSWORD`). Plaintext-in-profile stays
*allowed* (a file the user owns) but is no longer the only non-interactive option.

## Acceptance criteria

- [ ] With a username and no `--password`/profile password, `MGCONSOLE_PASSWORD`
      authenticates with no prompt.
- [ ] An explicit `--password` overrides `MGCONSOLE_PASSWORD`; a profile password
      is used only when neither flag nor env is set.
- [ ] With a username and none of flag/env/profile set, the hidden prompt still
      fires (interactive) and the existing empty-password error path is unchanged.
- [ ] An empty username (anonymous connection) ignores `MGCONSOLE_PASSWORD`
      entirely — no prompt, no auth.
- [ ] The env var is not echoed or logged; documented alongside the other
      `MGCONSOLE_*` overrides.
- [ ] Unit tests cover the precedence (flag > env > profile > prompt) and the
      anonymous-ignores-env case.

## Blocked by

None — extends `resolve_password`; can start immediately.

## Agent Brief

**Category:** enhancement
**Summary:** Add an `MGCONSOLE_PASSWORD` env-var step to the password precedence chain so authenticated connections can be made non-interactively without leaking the password.

**Current behavior:**
Password resolution takes a username, a password (from the `--password` flag or a
profile), and a hidden no-echo prompt closure. If the username is empty the
connection is anonymous and no password is sought; if a password is already
present it is used as-is; otherwise the hidden prompt fires. There is no
environment-variable path, so a non-interactive (piped/scripted) authenticated
run must either pass `--password` on the CLI (leaks to shell history and `ps`) or
store a plaintext password in `config.toml`.

**Desired behavior:**
An `MGCONSOLE_PASSWORD` environment variable is consulted between the explicit
flag and the profile password, giving the precedence chain:
`--password flag` > `MGCONSOLE_PASSWORD` > profile password > hidden prompt.
A script exports the env var and connects with no prompt and no CLI leak; an
explicit `--password` still wins; the hidden prompt remains the interactive
fallback when none is set and a username is given. An empty username (anonymous)
ignores the env var entirely. The env var must not be echoed or logged. The
keychain is deliberately *not* adopted (fragile over SSH / in containers / CI).

**Key interfaces:**
- The password-resolution function (today takes username, password, and a prompt
  closure) — should fold an env-var lookup into the precedence so the resolved
  password is flag-or-env-or-profile-or-prompt. Keep the prompt closure injectable
  for testing; the env read should be similarly testable (inject or read once at
  the call site) rather than reaching into the process environment deep in pure
  logic.

**Acceptance criteria:**
- [ ] With a username and no flag/profile password, `MGCONSOLE_PASSWORD`
      authenticates with no prompt.
- [ ] Explicit `--password` overrides `MGCONSOLE_PASSWORD`; a profile password is
      used only when neither flag nor env is set.
- [ ] With a username and none of flag/env/profile set, the hidden prompt fires
      and the existing empty-password error path is unchanged.
- [ ] An empty username ignores `MGCONSOLE_PASSWORD` — no prompt, no auth.
- [ ] The env var is not echoed or logged; it is documented alongside the other
      `MGCONSOLE_*` overrides.
- [ ] Unit tests cover precedence (flag > env > profile > prompt) and
      anonymous-ignores-env.

**Out of scope:**
- OS keychain / secret-service storage (explicitly rejected — environment
  fragility over SSH/containers/CI).
- Removing or changing the `--password` flag or the plaintext-in-profile option.
- Anonymous-connection behaviour.
