# Non-destructive Frontend switch: park and restore the Workbench view

Status: done

_Unblocked: `:repl` (issue 01), `:workbench` (issue 02), and editor-text carry
(issue 03) have all landed. Triaged to ready-for-agent on 2026-06-11._

## Context

ADR 0019 ships runtime switching between the REPL and the Workbench over a
preserved Session. v1 is deliberately **lossy on a round-trip**: a down-switch
(Workbench → REPL) keeps only the active Buffer's editor text; all inactive
Buffers and every Buffer's Result history are discarded, and an up-switch builds
one fresh Buffer. So flicking down to the REPL and back up loses your tabs.

That's an accepted v1 limitation, not the end state. This issue is the follow-up
to make round-trips non-destructive.

## What we want

Switching Workbench → REPL → Workbench should restore the Workbench view you
left: all Buffers (editor text + per-Buffer Result history) and the active Buffer
index, exactly as they were.

## Approach sketch (from the ADR discussion)

- The dispatch loop holds the suspended Workbench **view** — the `buffers` set,
  per-Buffer Result history, and `active` index — **alongside** the Session-state
  bundle, *not* inside it. Buffers stay Frontend-local; the Session bundle stays
  Frontend-neutral. Model it as the loop carrying an `Option<WorkbenchView>` that
  the Workbench detaches on `SwitchTo(Repl)` and reattaches on re-entry.
- On re-entry, **rebind the parked view to the live Session**, don't trust a
  snapshot. While you were down in the REPL you may have changed the active
  Database, mutated params/Settings, or opened/closed a Transaction — the parked
  Buffers must reattach to the *current* Session state, not the one captured at
  detach time. Reconciliation is the real work here, and the reason it was cut
  from v1.
- Decide what happens to the REPL line edited during the detour: does it seed /
  overwrite the active Buffer's editor text on return, or is it dropped? (Lean:
  if the editor text was carried down and edited, carry the edit back up into the
  same Buffer.)
- Queries run in the REPL during the detour ran against the same Session but are
  not Buffer-scoped, so they legitimately won't appear in any Buffer's Result
  history. That's expected, not a bug — note it so a reviewer doesn't "fix" it.

## Out of scope

- The Workbench gesture (key chord) for the downward flick — separate deferred
  increment from ADR 0019 (v1 is command-only).

## Blocked by

- Issue 02 (up-switch — round-trips must exist before they can be made

### Triage — agent brief

> *This was generated by AI during triage.*

**Category:** enhancement · **State:** ready-for-agent

Blockers all `done`; the dispatch loop, the `Outcome`/`WorkbenchExit` handoff, and
the `carry` String (issue 03) are in place to extend.

**The reconciliation is smaller than the ADR feared, because Buffers are already
purely Frontend-local** (`cli/src/workbench/state.rs`): a `Buffer` holds only
`editor` + `history` (per-Buffer results) + `view`/recall cursors — *no* session
state. read-only, active Database, params, Settings, and the transaction live in the
Session bundle, read fresh on every Workbench entry (`WorkbenchConfig` + the
on-connect reads in `run`). So restoring a parked view and reading live session state
*is* the rebind — there is no stale session field inside a Buffer to reconcile.

**Seams to use (they already exist):**
- `WorkbenchState::{take_active, install_active, checkout}` park/restore one Buffer's
  live top-level state into/out of `buffers[active]`. View-parking is the whole-`Vec`
  version of the same move.

**Plan:**
1. Add `pub struct WorkbenchView { buffers: Vec<Buffer>, active: usize }` in `state.rs`;
   re-export from `workbench/mod.rs`.
2. `WorkbenchState::detach_view(&mut self) -> WorkbenchView` — park the active Buffer
   (`buffers[active] = take_active()`), then `mem::take` the `buffers` Vec + `active`.
   `install_view(&mut self, WorkbenchView)` — set `buffers`/`active`, then
   `install_active(take(buffers[active]))`. Leave `new()` untouched (33 call sites).
3. `WorkbenchExit` gains `view: Option<WorkbenchView>` — `Some(detach_view())` only on
   `Outcome::SwitchTo`, `None` on `Quit`. Compute `carry` (issue 03) *before* detaching
   (detach moves the editor out).
4. `workbench::run` gains a `view: Option<WorkbenchView>` param: `new()` then
   `if let Some(v) = view { state.install_view(v) }`.
5. Dispatch loop (`main.rs`) holds `parked_view: Option<WorkbenchView>`. On Workbench
   entry pass `parked_view.take()`; seed `initial_editor` from `carry` (issue 03) **only
   when there is no parked view** (the restored view's active Buffer already holds its
   text — don't clobber it with the empty up-carry). On exit set
   `parked_view = exit.view`.

**Edge / non-bug to preserve:** the REPL up-carry is empty after a `:workbench` switch
(issue 03), so a restore keeps the active Buffer's parked text rather than overwriting
it. Queries run in the REPL during the detour are not Buffer-scoped and legitimately
do not appear in any Buffer's Result history — expected, not a bug.

**Acceptance:** Workbench → `:repl` → `:workbench` returns every Buffer (editor text +
per-Buffer Result history) and the active index intact, rebound to the current Session
(active Database / params / Settings / transaction as they are *now*, not at detach).

**Tests:** reducer-level park→install round-trip preserves buffers/history/active; the
dispatch-loop wiring (parked-view vs fresh-buffer seed) is the one untested edge —
cover the `WorkbenchState` view round-trip directly and assert a fresh launch (no
parked view) still builds one buffer.

### Implementation note (done)

> *This was generated by AI during triage.*

Shipped as planned in the brief: `WorkbenchView { buffers, active }` parked by the
dispatch loop, `detach_view`/`install_view` on `WorkbenchState` (the whole-`Vec`
form of the existing `take_active`/`install_active`), `WorkbenchExit.view` (`Some`
on a switch, `None` on quit), a `view` param on `workbench::run`, and a
`parked_view` accumulator in `main`'s dispatch loop that restores rather than
seeds a fresh Buffer. Confirmed: Buffers carry no session state, so reattaching
onto the live Session needs no per-field reconciliation.

The transaction marker is now rebound from the live Session on Workbench entry
(`WorkbenchConfig.tx`, read via `Session::transaction_state`), so a transaction
opened before a switch shows on re-entry.

**Deferred (small follow-up):** the active-Database *marker* is not rebound on an
up-switch. The `Session` exposes no current-database getter (the name is tracked
Frontend-side, set on `:use`), so faithfully restoring the `/db` marker needs the
dispatch-loop bundle to own the active-database name and seed both Frontends — the
same `carry`-style plumbing, but spanning both the REPL and the Workbench exits.
Queries still run against the Session's actual current database; only the marker
can lag. Not a regression from view-parking — the marker was already lost on the
issue-02 up-switch.
